## 1. Стиль (одна страница, которую не надо терять)

- **Маленькое ядро, бесконечная периферия.** Ядро знает «как», не «что». Это защита: ядро не может стать диктатом, потому что ему нечем диктовать.
- **Не добавляй слой, если он уже есть.** mini-electron → Termux уже даёт userland. method-as-window → `me` + shell уже даёт. pipe → Linux уже даёт. Новая сущность оправдана только тем, что нельзя выразить существующими.
- **Свобода — архитектура, а не право.** Не «они обязаны», а «их разрешение мне не нужно». Выносить мозг туда, куда вендор не дотянется, и оставлять тонкий слой.
- **Композиция вместо иерархии.** Два минимальных ядра через shell лучше одного умного, знающего про оба. Связь — обязательство. Беру только через явный контракт, минимально.
- **Решение «не делать» так же ценно, как «сделать».** Закрытый Этап 6 без кода — не «отложено», а решено. Записывать как `[DECISION]`, иначе через полгода снова откроешь.
- **TUI — точность, а не отступление.** GUI создаёт проблемы (сервер, транспорт, «упал — не достучался»). TUI их не создаёт. Эстетика — следствие точности.
- **Сомнение — это фильтр.** Два часа энтузиазма → трезвость → упрощение — нормальный цикл. Хорошие архитектуры рождаются из снятия слоёв.
- **Критерий, который не обманешь:** не «нравится идея», а «не могу без него». `tess_wm` прошёл. Если через месяц не используется — остановиться. Это не поражение, это фильтр.

## 2. Метод (не глагол)

> Linux: всё есть файл. Verb: всё есть действие. Me: метод.

**Метод = глагол + контракт.**

| | `verb` (глагол) | `me` (метод) |
|---|---|---|
| Что | Знает **как** (тело) | Знает **как + что** (`#@description:`) |
| Где | Вызывающий знает путь (`source`) | Реестр знает путь (`#@script:`) |
| Как | `source` + имя функции | Имя метода (`me <имя>`) |
| Кто знает | Вызывающий скрипт | Система (`me.conf`) |
| Изоляция | Нет (общее пространство имён) | Есть (субпроцесс) |

**Ключевое:** `verb` требовал `source` — неявная зависимость. `me` убрал: реестр знает путь, вызывающий знает только имя. Это не «удобнее» — это другая модель связи: явная (`#@script:`) вместо неявной (`source`).

**Паттерн рождения метода (всегда так):**

> Трение → боль → размышление (увидеть паттерн) → рождение метода → боль уходит → метод остаётся как порядок.

- Трение — место, где тратишь энергию не на задачу, а на обход.
- Боль — трение, которое перестало быть терпимым («не могу так», а не «неудобно»).
- Размышление — не «думать долго», а «увидеть, что все боли — одна боль: отсутствие контракта».
- Рождение — не «написать код», а «дать имя контракту». Код — следствие. Имя и контракт — причина.

**Две фазы метода:**

| | Из боли | Из возможности |
|---|---|---|
| Источник | Трение, которое не терпится | Инструмент уже есть |
| Вопрос | «Как убрать боль?» | «Что ещё можно, раз инструмент есть?» |
| Риск | Недодумать (боль вернётся) | Раздуть (делать ради делания) |
| Критерий | Боль ушла — готов | Перестал пользоваться — стоп |
| Пример | `calc`, `cit` | `tomv -s`, `cit -f`, `mp -lu` |

`tomv` в базе — из боли. `tomv -s` — из возможности: основа работает, добавляешь поиск, потому что инструмент позволяет. Это не раздувание. Критерий закрытия — не «боль ушла», а «я перестал танцевать». Пока танцуешь — имеет право расти.

## 3. Правило, которое надо записать капсом

**МЕТОД НЕ ПЕРЕПИСЫВАЕТ ДРУГОЙ МЕТОД — ТОЛЬКО ВЫЗОВ ЧЕРЕЗ КОНТРАКТ.**

- **ЗАПРЕЩЕНО:** (а) копировать тело/логику метода B в A; (б) патчить, подменять, «улучшать» поведение B из A (sed по файлу B, временная правка B, подмена переменных B); (в) читать внутренние переменные/функции B, не входящие в публичный контракт.
- **РАЗРЕШЕНО:** вызвать B как есть (`me_lib/B.sh args` или `me B args`), использовать его stdout/exit/файлы, которые B публично обещает.
- **Причина:** изменение B должно быть локальным и не ломать A. Копия расходится, патч создаёт скрытую зависимость от внутренностей.
- **Если A нужен «чуть другой B»** — это сигнал, что контракт B неполный: расширяй контракт B (осознанно, с риск-анализом) или делай B-вариант отдельным методом. Но не трогай B из A.
- **Нарушение = откат изменения A.**

**Почему это закон, а не вежливость:** A вызывает B через контракт → B можно менять внутри, A не заметит. A копирует B → изменение B не доходит, расходятся. A патчит B → A зависит от внутренностей, любое изменение B ломает A. «Использовать как есть» — единственный способ, при котором изменение B не ломает A.

**Ты уже живёшь по этому правилу:** `smet` вызывает `calc` через `me_calc` (не копирует), `cit` вызывает `me say` через `notify`, `fl` читает кэш `la` (не переписывает `la`). Правило не новое — оно уже true. Его надо только назвать и запретить отклонения.

### `calc` — `[FIX]`
`me_lib/calc.sh` был латентно сломан: `atan(1)`, `log10(1000)`, `log(e)` давали ошибки bc из-за порядка наивных `${expr//...}`-замен (`log` раньше `log10`, `e` везде, включая `sec`/`exp`).

- Замены через `sed -E` по границам токенов (`replace_token`), порядок «длинные первыми»: `log10`→`l10`, `log`→`l`, `atan`→`a`, `sin`→`s`, `cos`→`c`, `tan`→`t`, `pi`→`4*a(1)`, `e`→`2.718281828459045` (числовая константа, не `exp(1)` — иначе зацикливание/порча).
- Env-подстановка: только целые токены (`\b[A-Z_][A-Z0-9_]*\b`), длинные первыми, незаданные не трогаются.
