# AGENTS.md — Инструкция и трекер для LLM-агента

## ЖЁСТКИЕ ПРАВИЛА (НЕ НАРУШАТЬ)

* **ТЕЛА МЕТОДОВ — ТОЛЬКО СКРИПТЫ, НЕ В CONFIG:** Логика методов НЕ пишется внутри `me_method_*()` в `me.conf`. Любой метод, в котором есть реальная логика (проверки, циклы, парсинг, вызовы команд) — это отдельный исполняемый скрипт в `/root/.local/bin/me/me_lib/`. В `me.conf` у такого метода остаётся ТОЛЬКО обёртка из 6 строк: путь к скрипту (`$HOME/.local/bin/me/me_lib/<имя>.sh`) + проверка `-x` + вызов + сообщение об ошибке (образец — методы `net`/`netre`, ссылающиеся на `net.sh`/`netre.sh`). Писать логику прямо в конфиге — ЗАПРЕЩЕНО. Это правило распространяется и на НОВЫЕ методы, и на РЕФАКТОРИНГ старых: если метод разросся логикой — вынеси её в `me_lib/*.sh`, а в конфиг поставь обёртку-путь.
* **me.conf только в ~/.config/me/:** Единственный рабочий конфиг — `~/.config/me/me.conf`. `~/.local/bin/me/me.conf` — его бэкап/копия для удобства архивации проекта. Регистрация новых методов (добавление `#@method:` блоков) выполняется ТОЛЬКО в `~/.config/me/me.conf`. В проектном me.conf — никогда.
* **Конфиги плагинов в ~/.config/me/:** Рабочие файлы `*.conf` для плагинов (yfe.conf, tor.conf, gifx.conf) лежат в `~/.config/me/` — скрипт читает их оттуда (`CONFIG="$HOME/.config/me/<имя>.conf"`). Допустим fallback на старый путь `~/.local/bin/me/<имя>.conf` для не-мигрированных установок. Шаблон/копия для архивации и дистрибуции — в `pub/<имя>.conf`. ВАЖНО: файлы конфигов плагинов больше НЕ хранятся рядом со скриптом в `~/.local/bin/me/`.
* **ДВИЖОК `me` ПРАВИТЬ ТОЛЬКО ПО ЯВНОМУ ТРЕБОВАНИЮ ПОЛЬЗОВАТЕЛЯ. САМОСТОЯТЕЛЬНОЕ ИЗМЕНЕНИЕ ДВИЖКА (файл `me`, `pub/me.sh` и их ядро) БЕЗ РАЗРЕШЕНИЯ — АГЕНТУ ЗАПРЕЩЕНО.** Перед любым изменением движка агент ОБЯЗАН напомнить пользователю и предложить сделать слепок для отката: `me cit me` (или `me cit save ~/.local/bin/me/me`). Только после явного согласия пользователя и снятия слепка вносить правки. Это же касается синхронизации `pub/me.sh`.

## Парадигмы и принципы
* **KISS & Suckless:** Код должен быть максимально простым, модульным, прозрачным и без скрытых зависимостей.
* **Предсказуемость:** Выдача кода происходит строго по требованию. Изменения вносятся только в целевые компоненты.
* **Stream-ready:** Структурирование проекта должно быть явным и удобным для конвейерной обработки (POSIX-style).
* **Zero assumptions:** Если задача описана не полностью — не додумывай. Запроси недостающее.
* **Риск-анализ:** Прежде чем менять существующий код или архитектуру — агент ОБЯЗАН предупредить пользователя о ВСЕХ рисках: что сломается, что перестанет работать, какие методы потеряют функциональность. Изменения вносятся только после явного подтверждения.
* **Регрессия:** Прежде чем вводить новый метод, менять существующий или переписывать компонент — агент ОБЯЗАН проверить, что изменения не ломают другие методы и компоненты системы. Проверка: `bash -n` для всех скриптов, тестовый запуск затрагиваемых методов.
* **Не трогать бэкапы:** Агенту СТРОГО ЗАПРЕЩЕНО изменять, удалять или создавать файлы в каталогах с именами `bac`, `bacup`, `BAC`, `BACUP` и их аналогами. Это резервные копии — не рефакторить, не править, не чистить.
* **Explain architecture trade-offs:** Предлагая решение — развёрнуто поясни ключевые технические детали и почему выбран тот или иной подход. Не рассчитывай что пользователь знаком с терминами (subshell, eval-хук, etc.) — объясни кратко но содержательно.
* **СВЕРКА С GITHUB — СТРОГО webfetch: НИКАКИХ «похоже/вроде/визуально».** Любая проверка «локальный файл vs GitHub» выполняется ТОЛЬКО через `webfetch` (raw-URL), с сохранением содержимого GitHub в файл и последующим `diff`/`cmp` с локальным (или посимвольным сравнением). Категорически запрещено отвечать «похоже совпадает», «визуально одинаково», «кординаций нет» и т.п. без фактического сравнения. Если сравнение невозможно — прямо сказать, что файл не сверен, и предложить способ. Ответ всегда содержит конкретный результат (`diff` пуст / найдены различия: список).
* **No ~/.bashrc writes:** Методы, требующие правки `~/.bashrc` — **ЗАПРЕЩЕНЫ**. Любая задача, которая ведёт к модификации `~/.bashrc`, должна быть переосмыслена. Ищи обходные KISS/Suckless-пути: автономные скрипты, вызов через `eval` в рантайме, переменные окружения, симанты, `~/.profile`, `/etc/profile.d/`, автозагрузка через `me` и т.д. Если обходного пути нет — задача не принимается, запроси у пользователя альтернативу.
**Разграничение:** алиасы и прочий одноразовый мусор в `.bashrc` — табу. Но настройки, без которых проект не работает (например, `PATH` и `source` файла комплишна) — допустимы. Алиасы, которые забудут через месяц, запрещены.
* **Исключение:** `install_me.sh` — добавление `me` в `PATH` и `source ~/.local/bin/me/me_lib/me.completion` в `~/.bashrc`. Это единственные правки `.bashrc` во всём проекте. Не трогать, не рефакторить, не вырезать.

### 2026-09-14 — `me mp`: универсальный менеджер пакетов

**Проблема:** методы пульта жёстко завязаны на один пакетный менеджер (`me upgrade` различает pacman/apt/apk вручную), команды apt-pacman иметь нельзя без отдельного метода на каждый дистрибутив. Нужен единый метод `me mp`, который определяет ПМ один раз и переиспользует.

**Что сделано** (только `me_lib/mp.sh` + блок регистрации, движок не тронут):
- **Детект ПМ:** при первом вызове по `command -v` с приоритетом `pacman > dnf > apt` (по системам, где присутствует свой). Результат запоминается в `~/.cache/me/mp.pm` — повторная проверка не выполняется. `me mp -pm` показывает текущий ПМ, `me mp -pm reset` сбрасывает и переопределяет заново.
- **Карта опций** (общая парадигма apt): `-l` list (без имени — установленные: `apt list --installed` / `dnf list --installed` / `pacman -Q`), `-lu` list-upgradable (`apt list --upgradable` / `dnf list --upgradable` / `pacman -Qu`), `-s` search, `-S` show (`apt show` / `dnf info` / `pacman -Si`), `-i` install, `-r` reinstall (`apt install --reinstall` / `dnf reinstall` / `pacman -S`), `-d` remove, `-a` autoremove (pacman — через сироты `-Qtdq` + `-Rns`), `-u` update (`apt update` / `dnf makecache` / `pacman -Sy`), `-U` upgrade, `-UD` full-upgrade (`apt full-upgrade` / `dnf distro-sync` / `pacman -Syu`), `-es` edit-sources (`apt edit-sources` / открытие repo-файлов в `$EDITOR` / `/etc/pacman.conf`+`mirrorlist`), `-ms` modernize-sources, `-sat` satisfy (только apt; dnf/pacman — понятное сообщение «поддерживается только для apt»), `-pam` — вызов `/root/.local/bin/pam4/pam4.sh`.
- **Привилегии:** `PRIV()` — если не root, оборачивает в `sudo` (+ печать команды в stderr); read-операции (list/search/show) без sudo.
- **Найден и исправлен баг:** `return 1` на верхнем уровне скрипта (ветка `-es` dnf без repo-файлов) — bash ругается «return: возврат можно выполнить только из функции» → заменён на `exit 1`.

**Регрессия:** `bash -n` всех скриптов проекта OK (47 методов). Тесты на фейковых стабах (PATH+HOME в /tmp/opencode/mp_test): приоритет детекта pacman>dnf>apt, все 14 опций для каждого ПМ собираются в корректные команды, `-ms`/`-sat` на dnf/pacman отдают сообщение, `-es` dnf/pacman открывает файлы в `$EDITOR`, персистентность (первый запуск определяет+пишет state, второй — читает). Реальный apt: `me mp -l bash`, `me mp -S mpv`, `me mp -pm` прогонены через движок. `me int` разбирает все 14 вариантов (чистые команды без комментариев). Существующие методы не затронуты.

### 2026-09-05 — `me pict` (удалён)

**Статус:** метод `pict` (печать картинок в терминале) был создан и позже **удалён по решению пользователя** — результат разочаровал (ASCII/TrueColor-мозаика не даёт «настоящих» PNG с читаемым текстом). Удалено: блок `#@method: pict` из `~/.config/me/me.conf`, файл `me_lib/pict.sh`, кэш пересобран (`me cache-rebuild`). Движок `me` не затрагивался. Наработки (парсер XPM без eval, single-ESC фикс `$'\033'`) можно переиспользовать при необходимости.

**Было сделано ранее (для истории):**
- **Рендер half-block `▀`/`▄`:** каждая ячейка терминала = 2 вертикальных пикселя (верх → `48;2;...` bg, низ → `38;2;...` fg), честное соотношение сторон (~2:1 символа). TrueColor `\033[48;2;R;G;Bm` / `38;2;...`.
- **Форматы:** детект `magick` → fallback `convert` (IM 7.1.1-43 установлен, оба есть); конвертация в XPM на stdout (`xpm:-`), повторный resize `-filter lanczos -resize ${cols}x -unsharp 0x0.5` (гладко для фото). Без IM — только XPM, чисто строковый парсер, уменьшение вдвое (`halve`).
- **Парсер XPM без eval:** regex-заголовок `"W H NC CPP"` (с учётом trailing-пробела, который добавляет IM); цвета — `c #RRGGBB`, `#RGB` (расширяется), имена из `/usr/share/X11/rgb.txt` (ленивая загрузка, учтены ведущие пробелы в строках), `None`/`N` → прозрачный; скип `/* pixels */` комментария IM.
- **Прозрачность:** отсутствие цвета в ячейке → пробел; верх без низа → `▀` c bg; низ без верха → `▄` c fg.
- **stdin:** `me pict -` — читать XPM со стандартного ввода (в `mktemp`, trap на EXIT).
- **Отказоустойчивость подгонки:** если resize-`xpm:` пуст — восстановить из полноразмерного; ширина `<` 5 столбцов → 80.
- **Регистрация:** `#@method: pict` (cat: media) + `#@variants:` в `~/.config/me/me.conf`; кэш методов подхватывал автоматически.
- **Найденный баг (после первого прогона на реальном jpeg):** печатался литеральный текст `\033[48;2;...m▀` вместо цветных блоков. Причина: `"\033[...]"` в двойных кавычках bash НЕ даёт ESC-символ (bash интерпретирует `\` в двойных кавычках только перед `$`, `` ` ``, `"`, `\`, newline) — escape-последовательности в формате понимает только `printf`/`$'...'`. Фикс: ESC через `local esc=$'\033'` → `"${esc}[48;2;..."`. Признак в `cat -v`: правильные коды выглядят как `^[`, багованные — как текст `\033`.
