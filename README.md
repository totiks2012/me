
# me — пульт управления системой из терминала

**me** — это минималистичный CLI-фреймворк, который превращает сложные команды в простые методы. Один конфиг, одна команда, автокомплит, интерактивный выбор.

Вместо десятков алиасов в `.bashrc` — один файл `~/.config/me/me.conf` с методами, которые работают везде: в терминале, в скриптах, по SSH, на разных машинах.

---

## 🚀 Release Notes / Что нового в версии 2.0

Произведён кардинальный рефакторинг архитектуры `me`. Движок полностью переведён на декларативную схему **Zero-Eval / Direct Execution**.

### 🏗️ Архитектурные изменения

* **Полный отказ от `eval`:** Движок больше не загружает BASH-код методов в текущую сессию и не генерирует временные файлы функций в кэше. Это полностью исключает риски синтаксических сбоев при работе со сложными кавычками, heredoc и экранированием.
* **Чистый декларативный `me.conf`:** Конфигурационный файл больше не содержит исполняемого кода (`me_method_*()`). Теперь это строгий манифест метаданных с явным указанием пути к скрипту через тег `#@script: me_lib/<script>.sh`.
* **Автоматический сборщик `me make`:** Сканирует `me_lib/*.sh` на наличие маркера `#true_method` во 2-й строке и автоматически регистрирует новые методы в `me.conf` без ручного редактирования конфига.
* **Прямой диспетчер:** Движок моментально резолвит путь к скрипту и запускает его в отдельном субпроцессе. Изменение конкретного метода больше не требует сброса кэша и не влияет на остальные модули.
* **Мгновенный отклик:** Накладные расходы на вызов минимальны — резолвинг пути происходит за один проход `awk` по манифесту.

> **Важно:** Конфигурация `me.conf` старой версии несовместима с версией 2.0. Старый скрипт и его конфиг сохранены для истории в каталоге `me_old/`.

### 📋 Новый формат объявления методов в `me.conf`

```bash
#@method: mov
#@description: [cat: files] Массовое переименование файлов по маске
#@example: me mov -_ ; me mov "[]фото_1"
#@variants:
#   me mov -_                  # Замена - на _
#   me mov "[]фото_1"          # Нумерация с маской
#@script: me_lib/mov.sh

```

Для ведения ченджлогов смотрите файл `CHANGELOG.md`. В репозитории также публикуются снапшоты проекта с прежним кодом для возможности отката.

## Проблема, которую решает me

Алиасы в `.bashrc` работают, пока их 5–10. Когда их становится 30+ — начинается хаос:

* **Нет документации** — через месяц не помнишь, что делает `alias rd`.
* **Аргументы только в конец** — нельзя передать путь в середину команды.
* **Не работают в скриптах** — алиасы не видны в неинтерактивном bash.
* **Конфликты имён** — последний алиас перезаписывает предыдущий.
* **Нет проверок** — алиас не проверяет, установлена ли утилита, не обрабатывает ошибки.

В архитектуре 2.0 метод — это всегда изолированный скрипт с мета-тегами в `me.conf`.

Вместо километровых строк — простые глаголы. Всё остальное спрятано внутри методов.

## Первый метод за 30 секунд

В архитектуре 2.0 метод — это всегда отдельный исполняемый скрипт, а не встроенная функция в конфиге. Все скрипты методов по умолчанию размещаются в папке `~/.local/bin/me/me_lib/` (или по любому другому указанному пути).

### Шаг 1. Создай файл скрипта

Создай файл `~/.local/bin/me/me_lib/hello.sh`:

```bash
#!/usr/bin/env bash
#true_method
echo "Привет, терминал!"

```

> **Критически важно:** Вторая строка скрипта обязана содержать маркер `#true_method`. Именно он указывает сборщику `me make`, что перед ним тело метода, а не вспомогательный скрипт или библиотека.

Сделай его исполняемым: `chmod +x ~/.local/bin/me/me_lib/hello.sh`

### Шаг 2. Зарегистрируй метод в me.conf

**Вариант А: Автоматически через `me make` (Рекомендуется)**
Просто выполни команду:

```bash
me make

```

Сборщик сам найдёт файл `hello.sh`, увидит маркер `#true_method`, спросит описание с примером (или подставит дефолты) и автоматически допишет правильно сформированный блок в `me.conf`.

**Вариант Б: Вручную в конфиге**
Открой `~/.config/me/me.conf` и добавь объявление:

```bash
#@method: hello
#@description: Моя первая команда
#@example: me hello
#@script: me_lib/hello.sh

```

> **Примечание:** Можно прописывать как относительный путь от `~/.local/bin/me/` (`me_lib/hello.sh`), так и абсолютный путь к любому внешнему скрипту в системе (`/usr/local/bin/my_script.sh`). Главное — файл должен быть исполняемым (`chmod +x`).

## Интерактивное создание методов — `me create`

Если не хочется вручную открывать редактор и писать мета-блок — используй встроенный генератор:

```bash
me create

```

Скрипт задаст несколько вопросов:

* **Имя метода** — только латиница, цифры и подчёркивания (`^[a-z_][a-z0-9_]*$`).
* **Описание** — кратко, что делает метод.
* **Пример** — как вызывать метод (по умолчанию подставляется `me <имя>`).
* **Путь до скрипта** — путь к выполняемому файлу.

После ввода данных `me create`:

1. Генерирует блок с мета-тегами и путём до скрипта.
2. Создаёт заготовку исполняемого `.sh` скрипта с `shebang`, если файла ещё нет.
3. Безопасно добавляет запись в конец `me.conf`.

Пример сессии:

```text
$ me create
Имя метода: backup
Описание: Создать бэкап домашней директории
Пример: me backup
Путь до скрипта: /home/user/.local/bin/me/me_lib/backup.sh
Метод 'backup' создан в /home/user/.config/me/me.conf.
Запусти: me backup

```

## Автоматический сборщик реестра — `me make`

Для массовой автоматизации регистрации методов создана утилита `me make`. Это идемпотентный сканер реестра, который работает по следующему контракту:

1. **Сканирование:** `me make` проходит по всем скриптам вида `~/.local/bin/me/me_lib/*.sh`.
2. **Фильтрация по маркеру `#true_method`:** Утилита проверяет ровно **вторую строку** каждого файла. Если вторая строка содержит `#true_method`, файл признается официальным методом. Вспомогательные библиотеки и служебные скрипты без этой метки пропускаются.
3. **Проверка имени:** Имя файла (без расширения `.sh`) проверяется на валидность символов.
4. **Защита от дубликатов (Идемпотентность):** Если метод с таким именем или с таким путям скрипта уже зафиксирован в `me.conf`, сборщик его пропускает.
5. **Регистрация:** Для каждого нового метода спрашивается описание и пример (в TTY-режиме) и генерируется готовый блок `#@method: ... #@script: me_lib/<name>.sh`, который приписывается в конец `me.conf`.

---

### Работа с внешними скриптами

`me` 2.0 работает strictly со скриптами. В `me.conf` прописывается путь к файлу execution-слоя — функции BASH внутри конфига больше не поддерживаются ради безопасности и изолированности.

В качестве исполняемого файла вы можете использовать:

* `$HOME/.local/bin/my_script.sh` — любой скрипт в вашем `PATH`.
* `$HOME/.local/bin/me/me_lib/my_method.sh` — библиотечный скрипт из состава `me`.

## Ключевые возможности

### Интерактивный режим — `me int`

Не помнишь точное имя метода? Набери `me int` — откроется список всех методов с описаниями и примерами через `fzf`. Выбери нужный — команда попадёт в историю BASH, нажми `↑` и выполни.

### Документация встроена

* `me` — список всех методов с описаниями.
* `me -m <метод>` — подробная справка по конкретному методу.

### Версионирование файлов — `cit`

Храни снепшоты файлов в папке `.cit/` рядом с проектом, откатывайся, смотри `diff`, удаляй в корзину и восстанавливай. Не требует инициализации Git.

* `cit` (или `me cit`) — интерактивное меню.
* `cit -f` — финальная сборка с полным ченджлогом, создаёт `-F` копию.

### Экспорт и импорт методов — `share/import`

* `me share <метод>` — упаковывает метод со всеми зависимостями в `.tar.gz`.
* `me import <метод>` — устанавливает метод на другую машину (из файла, папки или URL).
Позволяет раскатывать персональный набор утилит на весь парк машин за секунды.

### Portable & Zero-Footprint

Весь `me` живёт в двух директориях: `~/.local/bin/me/` и `~/.config/me/`. Для переноса на другую Linux-машину достаточно скопировать их и добавить `me` в `PATH`. Никаких правок в `.bashrc` не требуется.

## Почему `me` кардинально превосходит классические алиасы и BASH-функции

Когда количество команд переваливает за пару десятков, стандартные механизмы BASH превращаются в хаос. `me` решает ключевые проблемы управления системой:

#### 1. Управление окружением и правами (`PATH`, `$USER` и `root`)

Главный подводный камень переноса скриптов в глобальные директории вроде `/usr/local/bin` — **потеря пользовательского контекста**.

* Скрипты в `/usr/local/bin` часто теряют переменные окружения (`$HOME`, `$XDG_CONFIG_HOME`, настройки D-Bus, сессий PulseAudio/PipeWire).
* В `me` вся экосистема строго локализована в `~/.local/bin/me/` и `~/.config/me/`. Методы всегда исполняются **в контексте вашей текущей пользовательской сессии**, сохраняя окружение графики, звука и D-Bus (X11/Wayland).

#### 2. Полноценная передача аргументов и ветвление

Алиасы в BASH — это простая подстановка текста. Вы не можете передать аргумент в середину команды или построить внутри алиаса условие `if/else`.

* В `me` каждый метод — это полноценный скрипт с прямым доступом к позиционным параметрам (`$1`, `$2`, `$@`), обработке флагов и валидации.

#### 3. Встроенная самодокументированность

Благодаря мета-тегам (`#@description:`, `#@example:`, `#@variants:`), вы получаете справку по любой команде прямо в терминале (`me -m <метод>`) или интерактивный каталог всего одной командой (`me int`).

#### 4. Прозрачный интерактивный поиск (`fzf`)

Интерактивный режим `me int` агрегирует все описания и примеры. Можно набрать ключевое слово (`video`, `audio`, `сеть`) и мгновенно найти нужный метод с предпросмотром.

#### 5. Исполнение в неинтерактивных скриптах и фоновых задачах

Алиасы BASH по умолчанию **не работают** внутри подшелов, cron-задач или внешних скриптов (`expand_aliases` выключен).

* Методы `me` являются явными исполняемыми файлами, вызванными через единый диспетчер, поэтому их можно использовать из оконных менеджеров (i3, XFCE, Sway), Cron или Systemd-таймеров.

#### 6. 100% Переносимость (Zero-Footprint)

Чтобы забрать всю свою рабочую среду со всеми утилитами, достаточно скопировать две папки: `~/.local/bin/me` и `~/.config/me`. Ваш `.bashrc` остается абсолютно чистым.

## Когда me нужен

* У тебя больше 5–10 алиасов.
* Ты администрируешь несколько машин (или live-системы).
* Ты вешаешь скрипты на хоткеи (i3/sway/bspwm).
* Хочешь чистый `.bashrc` без мусора.
* Нужен интерактивный выбор команд через `fzf`.

## Когда me не нужен

* У тебя 3–5 алиасов и всё устраивает.
* Ты не используешь терминал для рутинных операций.

## Безопасность и архитектурные рамки

* **Без опасного `eval`:** В версии 2.0 пульт полностью отказался от динамического выполнения кода. Конфиг `me.conf` является чистым манифестом метаданных. Каждый метод запускается как изолированный субпроцесс из указанного файла.
* **Контролируемые удаления:** В ядре пульта больше нет кэша тел функций (`~/.cache/me/methods`). Служебные очистки касаются строго временных директорий (`/tmp/me_check_*`, `/dev/shm`) и локальных служебных папок пульта (`del/cit`, `import`).
* **Аудит сторонних скриптов:** Поскольку методы выполняются с правами вашего пользователя, всегда проверяйте содержимое сторонних скриптов перед добавлением в `me_lib/` и импортом через `me import`!
