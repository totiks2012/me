
# me — пульт управления системой из терминала

**me** — это минималистичный CLI-фреймворк, который превращает сложные команды в простые методы. Один конфиг, одна команда, автокомплит, интерактивный выбор.

Вместо десятков алиасов в `.bashrc` — один файл `~/.config/me/me.conf` с методами, которые работают везде: в терминале, в скриптах, по SSH, на разных машинах.

## 🚀 Release Notes / Что нового в версии 2.0

Произведён кардинальный рефакторинг архитектуры `me`. Движок полностью переведён на декларативную схему **Zero-Eval / Direct Execution**.

### 🏗️ Архитектурные изменения
* **Полный отказ от `eval`:** Движок больше не загружает BASH-код методов в текущую сессию и не генерирует временные файлы функций в кэше. Это полностью исключает риски синтаксических сбоев при работе со сложными кавычками, heredoc и экранированием.
* **Чистый декларативный `me.conf`:** Конфигурационный файл больше не содержит исполняемого кода (`me_method_*()`). Теперь это строгий манифест метаданных с явным указанием пути к скрипту через тег `#@script: me_lib/<script>.sh`.
* **Прямой диспетчер:** Движок моментально резолвит путь к скрипту и запускает его в отдельном субпроцессе. Изменение конкретного метода больше не требует сброса кэша и не влияет на остальные модули.
* **Мгновенный отклик:** Накладные расходы на вызов минимальны — резолвинг пути происходит за один проход `awk` по манифесту.
Конфига me.conf старого me не совместима с новой конфигой , старый скрипт и его конфигу сохранил для истории в  каталоге me_old

### 📋 Новый формат объявления методов в `me.conf`

```bash
#@method: mov
#@description: [cat: files] Массовое переименование файлов по маске
#@example: me mov -_ ; me mov "[]фото_1"
#@variants:
#   me mov -_                  # Замена - на _
#   me mov "[]фото_1"          # Нумерация с маской
#@script: me_lib/mov.sh
```

## Проблема, которую решает me

Алиасы в `.bashrc` работают, пока их 5–10. Когда их становится 30+ — начинается хаос:

- **Нет документации** — через месяц не помнишь, что делает `alias rd`.
- **Аргументы только в конец** — нельзя передать путь в середину команды.
- **Не работают в скриптах** — алиасы не видны в неинтерактивном bash.
- **Конфликты имён** — последний алиас перезаписывает предыдущий.
- **Нет проверок** — алиас не проверяет, установлена ли утилита, не обрабатывает ошибки.

метод — это изолированный скрипт с мета-тегами в me.conf... (в 2.0 функций в конфиге нет).

##  Первый метод за 30 секунд 

(Новый формат)В архитектуре 2.0 метод — это всегда отдельный исполняемый скрипт, а не функция и не встроенная команда в конфиге.

Все скрипты методов по умолчанию размещаются в папке ~/.local/bin/me/me_lib/ (или по любому другому указанному пути).  

Шаг 1. Создай файл скрипта

Создай файл ~/.local/bin/me/me_lib/hello.sh:

```bash
#!/usr/bin/env bash
echo "Привет, терминал!"
```

Сделай его исполняемым: `chmod +x ~/.local/bin/me/me_lib/hello.sh`

Шаг 2. Зарегистрируй метод в me.conf

Открой ~/.config/me/me.conf и добавь объявление:   

```bash
#@method: hello

#@description: Моя первая команда

#@example: me hello

#@script: me_lib/hello.sh
```

Важно: Можно прописывать как относительный путь от `~/.local/bin/me/ (me_lib/hello.sh)`, 

так и абсолютный путь к любому внешнему скрипту в системе (/usr/local/bin/my_script.sh).

Главное — файл должен быть исполняемым (chmod +x).

## Интерактивное создание методов — `me create`

Если не хочется вручную открывать редактор и писать блок — используй встроенный генератор:

```bash
me create
```

Скрипт задаст несколько вопросов:

- **Имя метода** — только латиница, цифры и подчёркивания.
- **Описание** — кратко, что делает метод.
- **Пример** — как вызывать метод (по умолчанию подставляется `me <имя>`).
- **Путь до скрипта** — скрипт , который будет выполняться.

После ввода всех данных `me create`:
- генерирует блок с мета-тегами и и путём до скрипта;
- проверка bash -n была при eval, теперь create генерирует заготовку скрипта и добавляет запись в манифест
- добавляет метод в конец `me.conf`;
- выводит сообщение об успехе.

Пример сессии:

```
$ me create
Имя метода: backup
Описание: Создать бэкап домашней директории
Пример: me backup
тут приводим полный путь например /home/user/.local/bin/me/me_lib/bacup.sh
Метод 'backup' создан в /home/user/.config/me/me.conf.
Запусти: me backup
```

## Ключевые возможности

### Интерактивный режим — `me int`

Не помнишь точное имя метода? Набери `me int` — откроется список всех методов с описаниями и примерами. Выбери нужный — команда попадёт в историю, нажми `↑` и выполни.

### Документация встроена

- `me` — список всех методов с описаниями.
- `me -m <метод>` — подробная справка по конкретному методу.

### Версионирование файлов — `cit`

Храни снепшоты файлов в `.cit/` рядом с проектом, откатывайся, смотри diff, удаляй в корзину и восстанавливай. Не требует Git.

- `cit` (или `me cit`) — интерактивное меню.
- `cit -f` — финальная сборка с полным ченджлогом, создаёт `-F` копию.

### Экспорт и импорт методов — `share/import`

- `me share <метод>` — упаковывает метод со всеми зависимостями в `tar.gz`.
- `me import <метод>` — устанавливает метод на другую машину (из файла, папки или URL).

Это позволяет раскатывать набор методов на парк машин за минуты.

### Портативность

Весь `me` живёт в двух директориях: `~/.local/bin/me/` и `~/.config/me/`. Для переноса на другую Linux-машину достаточно скопировать их и добавить `me` в `PATH`. Никаких правок в `.bashrc` не требуется.

## Почему me, а не алиасы или bash-функции

Вместо сухой таблицы сравнительный разбор выглядит значительно убедительнее, если раскрыть реальные боли эксплуатации на практике.

---

### Почему `me` кардинально превосходит классические алиасы и BASH-функции

Когда количество команд переваливает за пару десятков, стандартные механизмы BASH превращаются в хаос. `me` решает ключевые проблемы управления системой:

#### 1. Управление окружением и правами (`PATH`, `$USER` и `root`)

Главный подводный камень переноса скриптов в глобальные директории вроде `/usr/local/bin` — **потеря пользовательского контекста**.

* Скрипт, ушедший в `/usr/local/bin`, часто запускается от другого пользователя или теряет переменные окружения (`$HOME`, `$XDG_CONFIG_HOME`, настройки D-Bus, медиа-сессий). Если же скрипт требует `sudo`, он и вовсе изолируется от пользовательского окружения.
* В `me` вся экосистема строго локализована в `~/.local/bin/me/` и `~/.config/me/`. Методы всегда исполняются **в контексте вашей текущей пользовательской сессии**, сохраняя все переменные, пути, права доступа и переменные графического/звукового окружения (PulseAudio/PipeWire, D-Bus, X11/Wayland).

#### 2. Полноценная передача аргументов и ветвление

Алиасы в BASH — это простая подстановка текста. Вы не можете передать аргумент в середину команды (например, вставить имя файла перед флагами) или построить внутри алиаса условие `if/else`.

* В `me` каждый метод — это полноценный скрипт. Вы имеете полный доступ к позиционным параметрам (`$1`, `$2`, `$@`), можете обрабатывать комбинации флагов, строить ветвления и валидировать входные данные до выполнения.



#### 3. Встроенная самодокументированность

Через месяц активной работы вспомнить, что делает алиас `alias xq='...'` или функция `f_net_chk()`, становится нереально. Приходится открывать `.bashrc` и разгребать код.

* `me` превращает документацию в часть архитектуры. Благодаря мета-тегам (`#@description:`, `#@example:`, `#@variants:`), вы получаете справку по любой команде прямо в терминале (`me -m <метод>`) или полный интерактивный каталог всего одной командой (`me` или `me int`).



#### 4. Прозрачный интерактивный поиск (`fzf`)

Алиасы и функции нельзя удобно искать по смыслу или категории — нужно либо помнящее память имя, либо `grep ~/.bashrc`.

* Интерактивный режим `me int` агрегирует все описания и примеры. Вы можете набрать ключевое слово (например, `video`, `audio`, `сеть`) и мгновенно найти нужный метод с предпросмотром его назначения.



#### 5. Исполнение в неинтерактивных скриптах и фоновых задачах

Алиасы BASH по умолчанию **не работают** внутри подшелов, cron-задач или внешних BASH-скриптов (`expand_aliases` выключен). Попытка вызвать алиас из фонового скрипта вернёт ошибку `command not found`.

* Методы `me` выбывают из этой проблемы: поскольку это явные исполняемые файлы, вызываемые через единый диспетчер, вы можете вызывать `me <method>` из любого места — из других скриптов, из хоткеев оконного менеджера (i3, XFCE, Sway) или из фоновых Cron/Systemd-таймеров.



#### 6. 100% Стопроцентная переносимость (Zero-Footprint)

Разрастающийся `.bashrc` превращается в «помойку», которую больно переносить на другие машины, Live-дистрибутивы или серверы.

* `me` полностью изолирован. Чтобы забрать всю свою рабочую среду со всеми десятками утилит, достаточно скопировать две папки: `~/.local/bin/me` и `~/.config/me`. Ваш `.bashrc` остается абсолютно чистым.

## Когда me нужен

- У тебя больше 5–10 алиасов.
- Ты администрируешь несколько машин (или live-системы).
- Ты вешаешь скрипты на хоткеи (i3/sway/bspwm).
- Хочешь чистый `.bashrc` без мусора.
- Нужен интерактивный выбор команд через `fzf`.

## Когда me не нужен

- У тебя 3–5 алиасов и всё устраивает.
- Ты не используешь терминал для рутинных операций.
- Нет желания централизовать управление командами.

 ## Безопасность и архитектурные рамки
 
 Без опасного eval: 
 В версии 2.0 пульт полностью отказался от динамического выполнения кода через eval.
 
 Конфиг me.conf является чистым манифестом метаданных и больше не содержит исполняемого BASH-кода.
 
 Каждый метод запускается как изолированный субпроцесс напрямую из указанного файла.   
 
 Контролируемые удаления: В ядре пульта больше нет кэша тел функций (~/.cache/me/methods). 
 
 Команды rm -rf внутри логики самого ядра применяются строго к служебным директориям — временным файлам (/tmp/me_check_*, /dev/shm) и локальным служебным папкам пульта (корзина del/cit, папка импорта import).
 Произвольные пользовательские директории ядро пульта не затрагивает.   
 
 ## !!! Аудит сторонних скриптов: 
 
 Поскольку методы являются обычными исполняемыми BASH-скриптами (chmod +x), они выполняются с правами вашего пользователя. 
 
 Всегда проверяйте содержимое сторонних скриптов и архивов методов перед их добавлением в me_lib/ и импортом через me import !!!
